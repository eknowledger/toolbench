Small interactive tools for any web page.

Write one function and one JSON file. Toolbench builds the form, runs the function, and draws the answer as fields, tables, charts or bytes.

LiveWhat a visitor gets

Every control in the tool was built from lines in its manifest. Click into one and those lines light up. The chart redraws as you type, because this tool is fast enough to run on every keystroke.

The whole tool is a function

It takes the form's values and returns a result. It has no idea it is on the web, so it runs the same in a page, in a worker, and in your test suite.

Then put it on any page, in any framework or none:

What you get

Five properties, each one checked by the test suite rather than promised.

Tiny
KB gzipped for the runtime, once per page, as measured on every change by the project's size check.
No dependencies
Both packages install nothing else. No framework on the page, and none inside the tool.
Lazy
A tool's code downloads when someone opens it. A card nobody clicks costs nothing but its markup.
Accessible
Real labels, keyboard operation and a status line on every tool. An error points at the input that caused it, and every chart also ships its numbers as a table.
Themeable
A dozen CSS custom properties restyle every tool, and a stylesheet of your own reaches the rest. This page sets them: the histogram above is wearing this site's colours and type.

Install

Version . Node 24 for development; any bundler for your site.

pnpm add @toolbench/sdk @toolbench/runtime

  1. Write the tool. A directory with tool.json, index.ts, known answers in cases.json, and a README.
  2. Register it. One call to defineToolHost, once per site.
  3. Put it on a page. <tool-host tool="your-tool">, anywhere in your HTML.
