Every tool in tools/, rendered by the runtime. Nothing on this page knows what any tool does.

Card mode

A card is a facade: it shows the tool's name and one input, and it downloads no tool code until you press it. Open the network panel, then click one — the chunk arrives on the click. Each card links to tools/<id>/ so the "one function and one JSON file" claim is a directory you can open, not a sentence.

The same cards, themed by the host

Identical markup. The only difference is a handful of CSS custom properties set on tool-host — no build step, no fork, no access to the runtime's internals.

A seeded card — what a server-rendered host emits

The result below is static HTML in the page source: no JavaScript ran to produce it. A host that renders on the server computes the tool's default result at build time and emits it as a seed, so the card is useful before anything loads, and becomes live when clicked. View source to see it. The data-seed attribute is all this page writes: a Vite plugin calls the SDK's seed() at build time and injects the result, so the seed cannot drift from the tool the way hand-written JSON does.

Source: tools/percentiles/

A card with room for two parts

The same card, told it has space for two of the tool's results rather than one. A tool whose answer is a number and a curve needs both: the number alone hides how steep the curve is, and the curve alone is a set of anonymous lines. Two inputs are marked primary here, because a rate without a duration sizes nothing.

Source: tools/queue-explorer/

A card that can open the rest in place

The same tool again with parts="1" more="expand". Click the card to open it, press Run, and the notice under the first result is a button rather than a line of text: it reveals the other two parts here instead of sending you to the tool's own page.

⚠️ A closed card never shows the button, and that is deliberate rather than missing: the whole facade is one big button, and a second button nested inside it could not be pressed without opening the card. A closed card's job is to open. Compare with the seeded card above, which still says on the full tool because it does not opt in.

Source: tools/percentiles/

Bytes — contract version 2

The bytes kind, added in contract version 2. Offsets, hex, printable gutter, and named highlight ranges that can start mid-row and wrap. A table can approximate this and gets alignment and spanning wrong, which is why it earned its own renderer. The legend is not decoration: colour alone tells a reader something is interesting without saying what, and tells a screen reader nothing.

Source: tools/utf8-bytes/

Code highlighting: a host hook

A code result is readable preformatted text unless the host passes highlight to defineToolHost. The runtime does not bundle a highlighter: that would roughly double it, and a host usually already has one. This bench passes a tiny demo highlighter that returns a Node, not a string, so the no-innerHTML rule still holds. Press Run to see it paint. Append ?plain-code to see the path a host that omits the hook still gets.

Retired and deprecated

A manifest can say status: "retired" or "deprecated". Retired does not run: the page explains and points at the replacement, so a bookmarked URL is not a 404 and is not a silent run. Deprecated still runs, with a marker a host can style, and it is not offered as a live card. These are the states nobody opens unless they are on the page.

A tool that does not exist

A host will get this wrong eventually, so it has to fail legibly.

Three display modes, one runtime: this is mode="card". The others are mode="page" and mode="embed". The failure-modes page is a fixture that times out and crashes on purpose, kept off this page so a first visit is not a deliberate error.
